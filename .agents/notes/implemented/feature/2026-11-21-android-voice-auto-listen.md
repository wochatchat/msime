# Agent Note: Android 键盘弹出后可自动开始语音聆听

Status: implemented

## Problem

重度语音输入用户每点一个输入框都要先按一下语音入口（长按空格、工具栏按钮或「更多工具」磁贴）才能开口：键盘弹出、手指已经放在屏幕上，却必须多做一次瞄准和按压。语音入口的三个既有方式都要求显式操作，没有一种「键盘一出现就能说话」的路径。

## Decision

语音页「识别」组在「启动方式」之后新增开关「进入输入框自动聆听」（本地设置 `platform.android.voice_auto_listen`，默认关、不同步——服务端同步字段表没有这个键，且它与设备录音权限和识别配置绑定，跟着账号走不合适）。打开后键盘弹出（`onWindowShown`）时延迟 350 毫秒安排一次自动开始：到点时重查开关、语音总开关、`voiceInsertionReady`（会话已建、连接可用、没有组字）、编辑器类型（密码框不开口）和识别配置，全部满足才经 `ImeVoiceEntry.startInKeyboard(keyRows, true)` 开始聆听；任何一个不满足就保持沉默，不提示、不转交识别窗口。

自动开始只覆盖键区内能跑的识别器（本机模型、豆包流式、上传式），由新方法 `ImeVoiceEntry.chooseAuto` 判断——它与 `choose` 同一条优先级，但系统识别服务（`Engine.PLATFORM`）返回 null：键盘刚弹出时 `SpeechRecognizer` 经常起不来或抢走编辑器焦点（既有笔记 #5553），自动开始的失败没有人工兜底，每次弹窗或灰蒙层都变成打扰。点按和长按入口不受影响，仍按 `choose` 走完整链路（含系统识别服务）。

判断规则集中在新的 `VoiceAutoListenPolicy`（`decide` / `editorAllows` / `START_DELAY_MILLIS`），服务只做接线；录制代次、停顿判停、上屏保护、结果面板与点按入口完全共用，没有第二条识别路径。面板第一句提示按引擎换成对应的开场文案（`autoHint`），其余不变。诊断新增 `VOICE_AUTO_LISTEN`（只进本机诊断包，追加在 `VOICE_ACTIVITY_LAUNCH` 之后不改已有序号）。排程在窗口隐藏、收起键盘时作废；到点时若已在聆听（手动入口抢先）则不重复开始。

设置搜索登记了「进入输入框自动聆听」「自动聆听」两个词条（PageId 的 VOICE 行）。

## Related notes audit

- [启动方式组合项](2026-10-30-android-combined-voice-trigger.md)：它管的是三个显式入口怎么并存，本篇是第四种开始方式，不改变任何既有入口的开关与派生逻辑；开关放在同一组、紧挨「启动方式」，用户在同一处看到全部开始方式。
- [键盘内语音识别（平台语音入键区）](../bug-fix/2026-10-08-android-platform-voice-in-keyboard.md)与 [voice-auto-insert](../bug-fix/2026-10-21-android-voice-auto-insert.md)：本篇复用键区内识别的整条链路，只加触发时机，不动结束与上屏规则。
- 检索 `voice` 相关 implemented 笔记，无既有「自动开始/免按开始」的归属，本篇独立成立。

## Alternatives considered

- 复用共享偏好 `touch_voice_shortcut` 加一个取值（如 `auto`），不新增本地键。能少一个设置项，但共享偏好三端共用，iOS/鸿蒙没有对应的自动开始实现，值会被同步到没有这个行为的设备上；且本项与设备录音权限绑定，放本地更合适。
- 把自动聆听做成「启动方式」的第三个选项。入口语义上更整齐，但它不替代启动方式——开着自动聆听的用户仍可能用长按锁定的按住说话，两个维度正交；并成一个选项会回到 #10309 刚拆掉的互斥老路。
- 到点时发现引擎不可用（含系统识别服务）就转交识别窗口或提示。被否：转交会在每个输入框上盖灰蒙层，提示会在没有配置识别服务的设备上变成每次弹出的常驻打扰；保持沉默才符合「自动」的语义，配置一次即可从设置页完成。

## Consequences

默认关，不打扰不开开关的用户；打开后每个文本输入框弹出键盘即开始录音——这本身就是一个高负担行为，所以准入必须从严（密码框、组字中、未就绪一律不开口），且系统识别服务用户开了开关也没有效果，说明文字里写明。豆包流式与上传式在自动开始后同样受「说完了 / 松手」控制，不会有无人值守的长录音；本地模型按停顿自动结束。延迟 350 毫秒是经验值：太早窗口未落地，太长则用户已经开始说话；若设备测试发现首帧更慢，调 `START_DELAY_MILLIS` 一个常量即可。
